## What Works

### 1. ToolCallLimitMiddleware for Preventing Tool Loops

**Problem**: Agent calls the same tool multiple times despite prompt instructions.

**Solution**: Use `ToolCallLimitMiddleware` from `langchain.agents.middleware`:

```python
from langchain.agents.middleware import ToolCallLimitMiddleware

agent = create_agent(
    model="openai:gpt-5-nano",
    system_prompt=SYSTEM_PROMPT,
    tools=[tavily_search, load_skill, plot_historical_data],
    middleware=[
        ToolCallLimitMiddleware(tool_name="tavily_search", run_limit=1, exit_behavior="end"),
        ToolCallLimitMiddleware(tool_name="load_skill", run_limit=1, exit_behavior="end"),
        ToolCallLimitMiddleware(tool_name="plot_historical_data", run_limit=1, exit_behavior="end"),
    ],
)
```

**Why it works**: This is a framework-level enforcement, not prompt-based. The middleware tracks tool calls and blocks excess calls regardless of what the model decides.

**Reference**: [LangChain Middleware Docs](https://docs.langchain.com/oss/python/langchain/middleware/built-in)

### 2. useRenderToolCall for Displaying Backend Tool Results

**Problem**: Need to display images generated by backend tools in the UI.

**Solution**: Use `useRenderToolCall` hook to intercept and render tool results:

```typescript
import { useRenderToolCall } from "@copilotkit/react-core";

useRenderToolCall({
  name: "plot_historical_data",
  render: ({ args, result, status }) => {
    let parsedResult = result;
    if (typeof result === "string") {
      try { parsedResult = JSON.parse(result); } catch {}
    }

    if (status === "complete" && parsedResult?.status === "success") {
      return (
        <div className="p-3 bg-green-50 rounded-lg">
          <img
            src={`/api/images/${parsedResult.image_id}`}
            alt={parsedResult.title}
          />
        </div>
      );
    }
    // ... handle other states
  },
});
```

**Why it works**: `useRenderToolCall` intercepts tool call events from the backend and allows custom React rendering. It receives the tool name, arguments, result, and status.

### 3. File-Based Image Serving via API Route

**Problem**: Images saved on host filesystem need to be served to browser.

**Solution**: Next.js API route that reads from `/tmp/plots/`:

```typescript
// app/api/images/[filename]/route.ts
export async function GET(
  _request: NextRequest,
  { params }: { params: Promise<{ filename: string }> }  // Next.js 15 requires Promise
) {
  const { filename } = await params;  // Must await in Next.js 15

  const imageFilename = filename.endsWith(".png") ? filename : `${filename}.png`;
  const imagePath = join("/tmp/plots", imageFilename);

  const imageBuffer = await readFile(imagePath);
  return new NextResponse(imageBuffer, {
    headers: { "Content-Type": "image/png" },
  });
}
```

**Why it works**: The LangGraph sandbox's subprocess breaks out to host, saving files to host's `/tmp/plots`. Next.js runs on host and can read these files directly.

**Next.js 15 Note**: Route params are now Promises and must be awaited.

### 4. Progressive Disclosure Pattern

**Problem**: Keep agent context small while maintaining full skill functionality.

**Solution**: Two-level disclosure:
1. System prompt shows only skill names/descriptions
2. Full instructions loaded on-demand via `load_skill()`
3. Script code never loaded into context - executed via subprocess

```python
# System prompt only shows:
## Skills (call load_skill for details)
- historical-plotter: Create line plots from historical time series data

# Full instructions loaded when agent calls load_skill("historical-plotter")
```

## What Doesn't Work (and Why)

### 1. useFrontendTool for Agent-Called Tools

**What we tried**: Register `display_image` as a frontend tool expecting the agent to call it:

```typescript
useFrontendTool({
  name: "display_image",
  handler: async ({ image_url, title }) => {
    setImages([...images, { url: image_url, title }]);
    return { success: true };
  },
});
```

**Why it failed**: Frontend tools registered with `useFrontendTool` are **NOT automatically available** to LangGraph agents using `create_agent`.

According to [GitHub Issue #1840](https://github.com/CopilotKit/CopilotKit/issues/1840):
- CopilotKit Actions are handled by the CopilotKit runtime/frontend system
- LangGraph's `ToolNode` only handles backend LangChain tools
- To make frontend actions work, you need to bind them via `state["copilotkit"]["actions"]`
- This requires a different agent architecture than `create_agent` provides

**The fix**: Use `useRenderToolCall` instead to render backend tool results.

### 2. Prompt Engineering Alone to Prevent Tool Loops

**What we tried**: Various prompt formulations:
- "Call each tool ONCE"
- "NEVER call the same tool twice"
- "After tool X succeeds, STOP immediately"
- "ABSOLUTE RULES - VIOLATIONS WILL CAUSE ERRORS"

**Why it failed**: LLMs don't reliably follow instructions about their own behavior. The model may:
- Misinterpret tool results as errors requiring retry
- Decide it needs more information and re-call tools
- Simply ignore the instructions

**The fix**: Use `ToolCallLimitMiddleware` for framework-level enforcement.

### 3. useCoAgentStateRender for Image Display

**What we tried**: Use agent state updates to display images:

```typescript
useCoAgentStateRender({
  name: "sample_agent",
  render: ({ state }) => {
    if (state.image_url) {
      // Display the image
    }
  },
});
```

**Why it failed**: The `create_agent` framework doesn't integrate with CopilotKit's state emission system. The agent's internal state isn't automatically broadcast to the frontend.

**When it would work**: If using a custom LangGraph graph with explicit `copilotkit_emit_state()` calls.

### 4. Base64 Data URIs in Tool Results

**What we tried**: Return base64-encoded images directly in tool results:

```python
return {
    "type": "image",
    "data": f"data:image/png;base64,{base64_string}",
}
```

**Why it's problematic**:
- Bloats agent context with large base64 strings
- Can hit token limits quickly
- Slows down agent responses

**The fix**: Save to filesystem, return only the image_id, serve via API route.

### 5. Relying on recursion_limit Alone

**What we tried**: Set low `recursion_limit` to prevent loops:

```python
.with_config({"recursion_limit": 10})
```

**Why it's insufficient**:
- Agent still loops until limit is hit, wasting time/tokens
- Error message to user is confusing ("Recursion limit reached")
- Doesn't actually fix the underlying issue

**The fix**: Combine with `ToolCallLimitMiddleware` for graceful handling.

## Implementation Details

### Backend Agent Configuration

```python
# agent.py
from langchain.agents import create_agent
from langchain.agents.middleware.summarization import SummarizationMiddleware
from langchain.agents.middleware import ToolCallLimitMiddleware

SYSTEM_PROMPT = f"""You are a data visualization assistant.
{get_skills_summary()}

## Workflow (call each tool exactly ONCE)
1. tavily_search → get data
2. load_skill("historical-plotter") → get format
3. plot_historical_data → create plot → returns image_id
4. Reply to user with the image_id → STOP

## Critical Rules
- Each tool can only be called ONCE per request
- After plot_historical_data succeeds, immediately reply to user and STOP
- On any error, tell user and STOP"""

agent = create_agent(
    model="openai:gpt-5-nano",
    system_prompt=SYSTEM_PROMPT,
    tools=[tavily_search, load_skill, plot_historical_data],
    middleware=[
        ToolCallLimitMiddleware(tool_name="tavily_search", run_limit=1, exit_behavior="end"),
        ToolCallLimitMiddleware(tool_name="load_skill", run_limit=1, exit_behavior="end"),
        ToolCallLimitMiddleware(tool_name="plot_historical_data", run_limit=1, exit_behavior="end"),
        SummarizationMiddleware(
            model="openai:gpt-5-nano",
            trigger=("fraction", 0.75),
            keep=("fraction", 0.10),
        ),
    ],
).with_config({"recursion_limit": 25})
```

### Tool Return Format

```python
# skill_tools.py
def plot_historical_data(...):
    # ... generate plot, save to /tmp/plots/{image_id}.png ...

    return {
        "type": "image",
        "status": "success",
        "image_id": image_id,  # e.g., "plot_abc123"
        "title": title,
        "data_points": len(dates),
    }
```

### Frontend Tool Rendering

```typescript
// GenerativeUIDemo.tsx
useRenderToolCall({
  name: "plot_historical_data",
  render: ({ args, result, status }) => {
    // Parse result
    let parsedResult = result;
    if (typeof result === "string") {
      try { parsedResult = JSON.parse(result); } catch {}
    }

    // Render based on status
    if (status === "executing") {
      return <LoadingSpinner title={args?.title} />;
    }

    if (status === "complete" && parsedResult?.status === "success") {
      return (
        <div>
          <img src={`/api/images/${parsedResult.image_id}`} />
        </div>
      );
    }

    if (parsedResult?.type === "error") {
      return <ErrorMessage message={parsedResult.message} />;
    }

    return <ProcessingMessage />;
  },
});
```

## Common Issues and Solutions

### Issue: "Route used params.filename. params is a Promise"

**Cause**: Next.js 15 changed route params to be Promises.

**Fix**: Update route handler signature and await params:
```typescript
export async function GET(
  _request: NextRequest,
  { params }: { params: Promise<{ filename: string }> }
) {
  const { filename } = await params;
  // ...
}
```

### Issue: Agent hits recursion limit

**Cause**: Agent keeps calling tools in a loop.

**Fix**: Add `ToolCallLimitMiddleware` for each tool.

### Issue: Images don't appear in UI

**Cause**: `useFrontendTool` tools aren't available to `create_agent`.

**Fix**: Use `useRenderToolCall` to render backend tool results instead.

### Issue: "Image not found" errors

**Cause**: Image file doesn't exist at expected path.

**Fixes**:
1. Verify subprocess saves to correct location (`/tmp/plots/`)
2. Check image_id matches filename
3. Ensure API route adds `.png` extension if missing

### Issue: Styles/theme not applying

**Cause**: `globals.css` not imported in layout.

**Fix**: Ensure `layout.tsx` imports the global styles:
```typescript
// app/layout.tsx
import { CopilotKit } from "@copilotkit/react-core";
import "@copilotkit/react-ui/styles.css";
import "./globals.css";  // <-- This import is required!

export default function RootLayout({ children }: {children: React.ReactNode}) {
  return (
    <html lang="en">
      <body>
        <CopilotKit runtimeUrl="/api/copilotkit" agent="sample_agent">
          {children}
        </CopilotKit>
      </body>
    </html>
  );
}
```

**Why it matters**: Without this import, Tailwind classes in components work but custom CSS variables and global overrides (like CopilotKit dark theme) won't be applied.

### Issue: useRenderToolCall render functions never trigger for backend LangGraph tools

**Cause**: Known bug (GitHub Issue #2622) where `useRenderToolCall` callbacks never fire for backend LangGraph tool calls when using `create_agent`.

**What happens**:
- The hooks register successfully
- But render callbacks are never invoked when backend tools execute
- Inline tool call status (executing/complete) is never displayed

**Workaround**: Use `useCopilotChat` hook's `isLoading` state to show activity:

```typescript
import { useCopilotChat } from "@copilotkit/react-core";

const { isLoading } = useCopilotChat();

// Activity Panel shows when agent is working
{isLoading && (
  <div className="activity-panel">
    <div className="animate-spin spinner" />
    <span>Agent Working...</span>
  </div>
)}
```

**Why this works**: Unlike `useRenderToolCall`, the `isLoading` state from `useCopilotChat` correctly reflects when the LangGraph agent is processing. It becomes `true` when a message is sent and `false` when the agent responds.

**Limitations**:
- No granular tool-level status (can't show "Searching..." vs "Plotting...")
- Generic activity indicator rather than specific tool feedback
- Works reliably but less informative than individual tool renderers would be

## Key Takeaways

1. **Use middleware, not prompts, for behavioral constraints** - `ToolCallLimitMiddleware` is the reliable solution for preventing tool loops.

2. **Frontend tools aren't automatically available to backend agents** - Don't assume `useFrontendTool` works with `create_agent`. Use `useRenderToolCall` instead.

3. **useRenderToolCall has limitations with LangGraph** - The render callbacks may not fire for backend tools (Issue #2622). Use `useCopilotChat().isLoading` as a fallback for showing activity.

4. **File-based image serving is more robust than base64** - Keeps agent context small, enables caching, works with standard img tags.

5. **Next.js 15 has breaking changes** - Route params are now Promises.

6. **Progressive disclosure keeps context small** - Only load what's needed, when it's needed.

7. **Always import globals.css in layout.tsx** - Without it, custom CSS variables and global theme overrides won't apply, even though Tailwind classes in components will still work.

8. **CopilotChat requires explicit height constraints for scrolling** - By default, the chat container grows infinitely. To make messages scrollable within a fixed viewport, apply these CSS rules to CopilotKit's internal classes:

```css
/* Make chat fill container */
.copilotKitChat {
  display: flex !important;
  flex-direction: column !important;
  height: 100% !important;
}

/* Messages area - scrollable */
.copilotKitMessages {
  flex: 1 1 0% !important;
  min-height: 0 !important;
  overflow-y: auto !important;
}

/* Input area - fixed at bottom */
.copilotKitInput {
  flex: 0 0 auto !important;
}
```

And ensure the parent container has a fixed height:
```tsx
<div className="w-96 flex flex-col h-screen">
  <CopilotChat className="flex-1 min-h-0" />
</div>
```

The key is `min-h-0` on the CopilotChat component and `flex: 1 1 0%` with `min-height: 0` on the messages container - this allows flex items to shrink below their content size, enabling overflow scrolling.
